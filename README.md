# Желток — бот и Mini App. Инструкция по запуску

*Документы. По шагам.* · версия 0.5 · всё бесплатно, собираем статистику спроса

## Как это устроено

- **Бот в Telegram** — 13 документов, анкета прямо в чате, дела и напоминания.
- **Mini App** — приложение со всеми 13 документами, разбитыми по разделам. Открывается кнопкой «Открыть Желток» под полем ввода.
- Приложение — это просто страница в интернете (бесплатно на GitHub Pages). Своего сервера и API у него нет: ответы уходят в бота через Telegram, бот перепроверяет каждый ответ, собирает документ и присылает два файла:
  1. **документ** — строгий, чёрно-белый, без рекламы: он уходит продавцу и в суд;
  2. **памятка «Желток»** — фирменная, со знаком, шагами и ссылкой на бота: она для человека, её пересылают друзьям.
- ИИ внутри нет: каждый документ стоит 0 ₽.

## Шаг 1. Бот на своём компьютере (20 минут)

1. Установи Python 3.11+ (python.org; на Windows — галочка «Add Python to PATH»).
2. В папке проекта: `pip install -r requirements.txt`
3. @BotFather → `/newbot` → имя «Желток» → адрес, например `zholtok_docs_bot`. Скопируй токен.
4. Скопируй `.env.example` в `.env`, впиши `BOT_TOKEN`, `KEY_RATE` (ключевая ставка ЦБ с cbr.ru — без неё бот не запустится), `ADMIN_IDS` (твой ID из @userinfobot), `BOT_LINK` (например `t.me/zholtok_docs_bot`).
5. `python bot.py` → напиши боту `/start`.

## Защищённый адрес для приложения («Мои дела»)

Одна команда на сервере (под root), когда бот уже установлен:

```
curl -sL alexcompton228-stack.github.io/Zholtok/h | bash
```

Скрипт ставит Caddy (веб-сервер, сам получает и продлевает бесплатный сертификат HTTPS), публикует приложение
и API бота на `https://<ip-сервера>.sslip.io/` (или вашем домене) и включает API. После этого:
- приложение отправляет документы откуда бы его ни открыли (кнопка под полем ввода, кнопка «Желток» слева, ссылка);
- в приложении есть «Мои дела»: этапы, отметка отправки, напоминания;
- работают ссылки сразу на документ: `t.me/имя_бота?startapp=otkaz_strahovka__vk1` (нужно один раз включить
  Main Mini App в @BotFather → Bot Settings → Configure Mini App, адрес — тот же https-адрес).

Кто спрашивает у API — проверяется по подписи Telegram (initData) или по токену, который бот вшивает в адрес
своей кнопки. Приложению сервер не доверяет: все ответы перепроверяются.

## Шаг 2. Mini App на бесплатном домене (GitHub Pages, 15 минут)

1. Зарегистрируйся на github.com (бесплатно). Имя пользователя станет частью адреса: `имя.github.io`.
2. Нажми **New repository** → название `zholtok` → **Public** → Create.
3. **Add file → Upload files** → перетащи **содержимое** папки `miniapp/` (файлы `index.html`, `app.css`, `app.js`, `logic.js`, `catalog.json` и папку `img`) → Commit.
4. **Settings → Pages** → Source: *Deploy from a branch* → Branch: `main`, папка `/ (root)` → Save.
5. Через 1–2 минуты приложение будет по адресу `https://имя.github.io/zholtok/`. Открой в браузере — должен появиться главный экран «Разберёмся с вашей ситуацией». Вне Telegram отправить документ нельзя: приложение честно скажет открыть его из чата.
6. Впиши адрес в `.env`: `MINIAPP_URL=https://имя.github.io/zholtok/` и перезапусти бота.
7. В боте нажми `/start` — под полем ввода появится кнопка **«Открыть Желток»**.

Важно:
- **Открывай приложение именно этой кнопкой.** Только кнопка под полем ввода позволяет приложению передать ответы боту. Кнопку меню бота (слева от поля) на Mini App не настраивай — оттуда отправка не работает.
- В репозитории нет секретов и личных данных — только интерфейс, поэтому публичный репозиторий безопасен.
- Когда купишь свой домен: GitHub → Settings → Pages → Custom domain. Поменяй `MINIAPP_URL`.
- Доступность GitHub Pages в РФ может меняться. Если у части пользователей не открывается — та же папка без изменений заливается на Netlify или любой хостинг с HTTPS.

**Поменял вопросы в `catalog.yaml`?** Запусти `python build_miniapp.py` и заново загрузи `miniapp/catalog.json` на GitHub. В приложение попадают все документы каталога; бот берёт список из того же `miniapp/catalog.json`, так что в `.env` ничего менять не нужно.

## Шаг 4. Сервер 24/7

**Быстрый путь (с телефона):** купить VPS на Ubuntu в РФ, открыть веб-консоль в личном кабинете хостинга и вставить одну команду (подставив свой логин GitHub):
```
bash <(curl -fsSL https://raw.githubusercontent.com/alexcompton228-stack/Zholtok/main/deploy/install.sh) https://github.com/alexcompton228-stack/Zholtok.git
```
Скрипт сам поставит всё нужное, спросит токен и настройки (они сохранятся только на сервере) и запустит бота службой. Повторный запуск той же команды обновляет код.

**Вручную:**

Пока бот запущен на твоём компьютере, он работает, только когда компьютер включён. Для запуска нужен VPS **в России** (персональные данные): Timeweb Cloud, Selectel, REG.RU, самый дешёвый Ubuntu — порядка 200–400 ₽/мес (моя прикидка, проверь цены).
```
sudo apt update && sudo apt install -y python3-venv
cd ~/zholtok-bot && python3 -m venv venv && venv/bin/pip install -r requirements.txt
```
Файл `/etc/systemd/system/zholtok.service`:
```
[Unit]
Description=Zholtok bot
After=network.target

[Service]
WorkingDirectory=/root/zholtok-bot
ExecStart=/root/zholtok-bot/venv/bin/python bot.py
Restart=always

[Install]
WantedBy=multi-user.target
```
`sudo systemctl enable --now zholtok`, логи: `journalctl -u zholtok -f`.

Mini App при этом остаётся на GitHub Pages — сервер ему не нужен.

## Где живут данные

- В приложении ответы хранятся **на телефоне пользователя**, пока он заполняет анкету, и ещё сутки после отправки (чтобы можно было исправить и отправить заново), потом удаляются. GitHub Pages данных не видит.
- В боте ответы в памяти до выдачи файла, затем стираются. На диске — только отметка о согласии, дела (тип документа и этап), напоминания, обезличенная статистика.
- Бот перепроверяет всё, что пришло из приложения, и не выдаёт документ дважды на одну отправку.

## Безопасность

- **Ключей и секретов в браузере нет.** Mini App — это только интерфейс, вопросы и картинки. Токен бота хранится только на сервере в `.env` (права 600, в `.gitignore`), в репозиторий и архив не попадает.
- **Облачной базы (Supabase и т.п.) нет**, поэтому RLS настраивать не нужно. Данные — в файле SQLite на сервере, снаружи он недоступен. Ответов анкет и готовых документов там нет, только дела (тип документа и этап), напоминания и обезличенная статистика.
- **Никаких порядковых номеров:** дела обозначаются случайными кодами, отправки из приложения — случайными id. Каждое действие с делом проверяет, что оно принадлежит тому, кто нажал кнопку; подделанные кнопки ничего не открывают и не роняют бота (есть тест).
- **Всё, что приходит из приложения, перепроверяется ботом** (варианты ответов, даты, суммы), повторная отправка не выдаёт документ дважды.
- Если токен бота где-то засветился: @BotFather → `/revoke`, новый токен — в `.env` на сервере, `systemctl restart zholtok`.

## Статистика

`/stats` (только для ADMIN_IDS): сколько документов выдано, воронка за 7 дней (`start → card → fill → preview → issued`), источники, дела по этапам. Документы из приложения помечаются источником `miniapp`.

Ссылки для рекламы с меткой: `t.me/ТВОЙ_БОТ?start=vozvrat_brak__pikabu1` — откроет карточку документа и запишет источник `pikabu1`.
